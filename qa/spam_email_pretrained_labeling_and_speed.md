# 垃圾邮件模型：预训练基座、数据标注与处理速度

## 问题

1. 是否有已经训练好的模型可以作为基座使用？
2. 手里有很多 EML 格式的邮件，但是没有标注，是否需要标注后才能训练？
3. TF-IDF 与逻辑回归方案处理邮件的速度如何？如果要求快速处理，应该怎样设计？

## 一、是否有训练好的模型可以作为基座

有，但可以分成三类。

### 1. 可以直接使用：SpamAssassin

Apache SpamAssassin 是成熟的开源垃圾邮件过滤系统，综合使用邮件头和正文规则、贝叶斯分类、DNS 黑名单等机制，可以直接扫描邮件。

参考：[Apache SpamAssassin 官方网站](https://spamassassin.apache.org/)

优点：

- 可以直接处理邮件，不需要先训练自己的模型。
- 已经包含大量反垃圾规则。
- 能解析邮件头、HTML、URL 等邮件特有信息。
- 可以输出垃圾邮件分数。
- 支持根据自己的正常邮件和垃圾邮件继续训练贝叶斯过滤器。

不足：

- 更像“规则系统 + 统计模型”，不是一个单独的现代机器学习模型。
- 规则和 DNS 查询可能影响速度。
- 对中文邮件和特定业务邮件不一定完全适配。

适合将其用于：

```text
第一阶段过滤器
+
为未标注 EML 生成初始伪标签
+
与自己的机器学习模型组合
```

### 2. 可以作为语言基座：DistilBERT 等模型

例如 `distilbert-base-multilingual-cased` 支持包括中文在内的多种语言，并且相比原始多语言 BERT 更小、更快。

参考：[DistilBERT 多语言模型卡](https://huggingface.co/distilbert/distilbert-base-multilingual-cased)

需要注意：

- 它是预训练语言模型，不是已经训练完成的垃圾邮件分类器。
- 仍需要带有“正常/垃圾”标签的数据进行微调。
- 推理速度明显慢于 TF-IDF + 逻辑回归。
- 邮件很长时，还需要考虑截断、分段和批处理。

网上也有社区发布的垃圾邮件分类模型，但其数据来源、语言、标签定义和安全性可能不清楚，不建议直接作为生产系统的唯一判断依据。

### 3. 使用公开垃圾邮件数据训练基础模型

可以使用公开的 Enron Spam、SpamAssassin Public Corpus 等带标签数据，先训练基础模型，再用自己的邮件进行校准或微调。

这种方法比完全从零开始更方便，但存在领域偏移：

```text
公开英文垃圾邮件
≠
自己的中文邮件、业务通知和公司往来邮件
```

因此，公开数据可以提供初步识别能力，但最终仍然需要一部分来自真实业务环境的邮件。

### 4. 推荐组合

如果强调速度和落地性，可以采用：

```text
SpamAssassin 提供规则分数
          +
公开数据训练基础模型
          +
少量自有标注邮件校准
          +
TF-IDF + 逻辑回归
```

## 二、未标注 EML 是否需要标注

如果要训练“正常邮件/垃圾邮件”的监督分类模型，最终必须有一定数量的标注数据。

模型需要看到类似下面的训练样本：

```text
邮件 A → 正常
邮件 B → 垃圾
邮件 C → 垃圾
邮件 D → 正常
```

只有未标注邮件时，TF-IDF 可以提取特征，K-Means 可以进行聚类，但模型不知道哪个簇代表垃圾邮件，因此不能可靠地学习最终分类目标。

不过，不需要一开始人工标注全部邮件。

### 1. 利用已有信息生成候选标签

可以检查 EML 中是否存在：

- `X-Spam-Status`
- `X-Spam-Flag`
- `X-Spam-Score`
- 邮箱系统添加的垃圾邮件头
- 邮件原来所在的文件夹
- 已知黑名单或白名单
- 用户曾经执行的“移入垃圾箱”操作

例如：

```text
来自 Spam 文件夹                   → 候选垃圾邮件
来自已发送、联系人或重要邮件文件夹  → 候选正常邮件
X-Spam-Flag: YES                   → 候选垃圾邮件
```

这些信息可以降低标注成本，但不应直接视为百分之百正确的最终标签。

### 2. 使用 SpamAssassin 生成弱标签

可以让 SpamAssassin 扫描全部 EML：

```text
高分邮件 → 候选垃圾
低分邮件 → 候选正常
中间区域 → 暂不确定，交给人工审核
```

SpamAssassin 支持自动学习，但官方文档建议尽可能补充监督训练。单纯强化系统自身的判断，可能不断积累错误。

参考：[SpamAssassin `sa-learn` 文档](https://spamassassin.apache.org/full/3.0.x/dist/doc/sa-learn.html)

### 3. 优先人工审核不确定样本

不必完全随机抽取邮件进行标注，可以优先标注：

- 模型概率接近 `0.5` 的邮件。
- SpamAssassin 和机器学习模型意见不一致的邮件。
- 新发件人、新域名和新模板。
- 被模型错误拦截的正常邮件。

这是主动学习思路，可以使用较少的人工标注获得更大提升。

### 4. 保留纯人工测试集

这是非常重要的一点：

```text
训练数据可以包含伪标签
最终测试集必须尽量由人工确认
```

否则模型可能只是学会模仿 SpamAssassin，而无法判断其实际准确率。

### 5. 建议标注数量

初始阶段可以考虑：

- 人工确认 1,000～3,000 封邮件，建立第一个模型。
- 正常邮件和垃圾邮件都要有足够样本。
- 如果垃圾邮件比例较低，可以主动多抽取垃圾候选。
- 单独保留至少数百封较新的人工确认邮件作为测试集。

这个数量不是绝对标准。邮件模板越集中，需要的标注越少；来源、语言和内容越复杂，需要的标注越多。

scikit-learn 也提供 `SelfTrainingClassifier`、`LabelPropagation` 等半监督学习方法，但这些方法不能消除对可靠种子标签和最终人工测试集的需求。

参考：[scikit-learn 半监督学习接口](https://scikit-learn.org/stable/api/sklearn.semi_supervised.html)

## 三、模型处理邮件的速度

TF-IDF + 逻辑回归是一种速度很快的文本分类方案。

单封邮件的处理流程为：

```text
读取 EML
→ MIME 和字符集解析
→ 提取主题与正文
→ HTML 转纯文本
→ 提取 URL 等统计特征
→ TF-IDF 转换
→ 逻辑回归计算概率
```

逻辑回归的核心计算只是稀疏向量与权重的乘积，通常不是主要性能瓶颈。更可能耗时的是：

- EML 和 MIME 解析。
- HTML 转纯文本。
- 大附件解码。
- DNS、域名信誉或远程黑名单查询。
- 很长邮件的文本特征提取。
- 磁盘随机读取大量小文件。

### 1. 大致性能量级

下面是工程量级估计，最终必须使用实际邮件和服务器进行基准测试：

| 方案 | 单封延迟 | 吞吐特点 |
|---|---:|---|
| TF-IDF + 朴素贝叶斯 | 通常非常低 | 最快 |
| TF-IDF + 逻辑回归 | 通常毫秒级 | 很适合高吞吐 |
| TF-IDF + LinearSVC | 通常毫秒级 | 速度快，但概率输出不方便 |
| SpamAssassin 本地规则 | 一般较快 | 启用网络查询后延迟可能上升 |
| DistilBERT CPU | 通常数十至数百毫秒级 | 长邮件时更慢 |
| DistilBERT GPU 批处理 | 吞吐较高 | 存在批处理等待和 GPU 成本 |
| 大语言模型 API | 通常最慢 | 还有网络延迟和调用费用 |

如果要求快速处理，不建议将 Transformer 作为所有邮件都必须经过的主分类器。

### 2. 推荐的高速分层架构

```text
第一层：极快规则
- 白名单
- 黑名单
- 已知发件人
- 已知恶意域名
- 邮件大小限制

第二层：TF-IDF + 逻辑回归
- 本地 CPU 推理
- 输出垃圾邮件概率

第三层：只处理少量不确定邮件
- SpamAssassin 深度规则
- Transformer
- 人工审核
```

例如：

```text
模型概率 < 0.20  → 直接判定正常
模型概率 > 0.90  → 直接判定垃圾
0.20～0.90       → 进入更精细但更慢的检测
```

这样绝大多数邮件只经过快速模型，昂贵检测只用于边界样本。

### 3. 高速实现注意事项

- 让模型常驻内存，不要每处理一封邮件就重新加载模型。
- 批量调用 `transform()` 和 `predict_proba()`。
- 限制正文最大长度，例如只处理主题和前若干万字符。
- 默认不解码附件正文，只提取附件名、扩展名、数量和大小。
- 将 DNS 和信誉查询改为异步操作，并添加本地缓存。
- 对邮件内容计算哈希，重复模板直接复用结果。
- 同时保留词级和字符级 TF-IDF，但限制 `max_features`。
- EML 解析和模型推理可以使用生产者—消费者队列并行处理。
- 对磁盘上的大量小文件预先建立索引，或者批量读取。

## 四、针对当前条件的推荐路线

当前条件是：

- 已有大量未标注 EML。
- 希望训练自己的垃圾邮件模型。
- 对处理速度要求较高。

建议采用下面的实施路线：

```text
大量未标注 EML
    ↓
解析并去重
    ↓
提取已有垃圾邮件头、文件夹和规则分数
    ↓
人工确认一小批高价值样本
    ↓
训练字符/词级 TF-IDF + 逻辑回归
    ↓
设置高置信度自动分类和不确定区间
    ↓
持续收集误判样本并定期重新训练
```

## 五、结论

1. 有现成基础能力可用：优先考虑 SpamAssassin 和公开数据。多语言 DistilBERT 可以作为后续语义模型基座，但它不是开箱即用的垃圾邮件分类器。
2. 不必标注所有 EML，但监督模型至少需要一批可靠标注。伪标签可以扩大训练集，纯人工确认的测试集不可省略。
3. TF-IDF + 逻辑回归很适合高速需求，模型计算本身通常很快；系统瓶颈更可能出现在 EML、HTML、附件和网络信誉查询上。
