# 使用 K-Means 辅助垃圾邮件标注

## 问题

手里有很多未标注邮件，是否可以先使用 K-Means 对邮件进行聚类，把垃圾邮件聚到一起后统一打标签，再训练监督模型，以此节省标注时间？

## 结论

可以使用 K-Means 辅助标注，确实能够节省时间；但不能指望它自动把所有垃圾邮件聚到同一个簇，再给整个簇统一贴标签。

更准确的定位是：

```text
K-Means = 帮助整理和抽样邮件
人工确认 = 决定真正标签
监督模型 = 最终执行垃圾邮件识别
```

## 一、为什么垃圾邮件不会自然聚成一类

K-Means 根据邮件内容的相似程度聚类，并不理解“垃圾”这个业务概念。

它更可能得到这样的簇：

```text
簇 1：发票、付款和财务邮件
簇 2：会议通知
簇 3：商品促销
簇 4：账户验证
簇 5：快递通知
簇 6：英文邮件
簇 7：招聘邮件
```

但是，同一个簇中可能同时存在正常邮件和垃圾邮件。例如，“账户验证”簇可能包含：

- 正常的密码重置通知。
- 正常的登录验证码。
- 伪造银行发送的钓鱼邮件。
- 诱导用户点击恶意链接的垃圾邮件。

反过来，垃圾邮件也可能分散在许多不同簇中：

- 商品广告。
- 虚假中奖。
- 色情内容。
- 钓鱼邮件。
- 恶意附件。
- 贷款推广。

因此，通常不存在一个天然的“垃圾邮件簇”。

## 二、如何利用聚类节省标注时间

推荐将聚类用于“分组后抽样标注”。

### 第一步：解析和清洗 EML

从每封邮件中提取：

- `Subject`。
- 纯文本正文。
- HTML 转换后的正文。
- 发件人和发件人域名。
- 回复地址。
- URL 数量。
- 附件数量和附件类型。
- SPF、DKIM、DMARC 等邮件头。
- 邮件原来所在的文件夹。

不要把附件二进制内容直接放入 TF-IDF。

### 第二步：先进行去重

实际邮件中经常存在大量相同或近似相同的群发模板。

可以按照下面的顺序去重：

```text
完全相同的正文
    ↓
清除日期、订单号、收件人姓名等变量
    ↓
计算文本指纹
    ↓
合并近似重复模板
```

如果 10,000 封邮件实际上来自 300 个模板，只需重点标注这些模板的代表邮件。去重带来的标注节省可能比聚类还大。

### 第三步：将邮件转换为特征

初始方案可以使用字符级 TF-IDF：

```python
TfidfVectorizer(
    analyzer="char",
    ngram_range=(2, 5),
    min_df=2,
    max_features=100_000,
)
```

也可以将词级和字符级 TF-IDF 特征结合起来。

TF-IDF 维度通常很高，不适合直接运行标准 K-Means。建议先使用 `TruncatedSVD` 降到大约 100～300 维：

```text
TF-IDF
  ↓
TruncatedSVD
  ↓
K-Means
```

这里应使用 `TruncatedSVD`，而不是直接使用普通 PCA，因为 TF-IDF 通常是稀疏矩阵。

### 第四步：划分多个簇

不要只设置：

```text
k = 2
```

K-Means 不会因为设置两个簇，就自动得到“正常”和“垃圾”。

如果有数万封邮件，可以尝试几十到几百个簇，例如：

```text
k = 50、100、200
```

具体数量取决于邮件模板、语言和主题的丰富程度。

### 第五步：查看每个簇的代表样本

每个簇优先查看：

- 距离质心最近的邮件：代表该簇的典型内容。
- 距离质心最远的邮件：可能是边界样本或错误归类的样本。
- 随机抽取的若干邮件。
- 来自不同发件人和不同时间的邮件。

例如，每个簇可以先人工检查 10～20 封。

### 第六步：只对高纯度簇批量标注

假设抽查某个簇的 20 封邮件：

```text
20 封全部是同一种促销垃圾邮件
```

这个簇可能具有较高纯度，可以暂时批量标为候选垃圾邮件。

如果抽查结果是：

```text
12 封垃圾邮件
8 封正常邮件
```

则不能给整个簇统一打标签，需要：

- 进一步拆分这个簇。
- 增加抽查数量。
- 或者逐封标注其中的邮件。

可以给批量标注设置严格门槛，例如：

```text
抽查 20 封
至少 19 封标签一致
才允许批量赋予候选标签
```

即使满足条件，也应将这些标签记录为聚类传播标签，而不是人工确认标签。

## 三、记录标签来源和可信度

推荐的标注表包含：

| 字段 | 含义 |
|---|---|
| `email_id` | 邮件唯一编号 |
| `label` | `ham` 或 `spam` |
| `label_source` | 标签来源 |
| `confidence` | 标签可信度 |
| `cluster_id` | 所属簇 |
| `reviewed` | 是否经过人工确认 |

例如：

```text
人工确认：
label_source = manual
confidence = 1.0

邮件原有垃圾标记：
label_source = existing_header
confidence = 0.9

高纯度簇传播：
label_source = cluster_propagation
confidence = 0.8

模型自动预测：
label_source = model_prediction
confidence = 模型概率
```

这样，后续发现某类自动标签不可靠时，可以方便地排除或重新审核。

## 四、推荐的完整流程

最佳实践不是只执行一次 K-Means，而是采用迭代式流程：

```text
未标注 EML
    ↓
去重与模板合并
    ↓
TF-IDF + TruncatedSVD + K-Means
    ↓
从每个簇抽取代表邮件
    ↓
人工标注一批高价值样本
    ↓
训练 TF-IDF + 逻辑回归
    ↓
找出模型最不确定的邮件
    ↓
继续人工标注
    ↓
重新训练
```

模型最不确定的邮件通常是垃圾概率接近 `0.5` 的邮件。这种主动学习方法通常比持续随机标注更有效。

## 五、标注预算示例

假设有 100,000 封邮件，可以这样处理：

1. 完全去重和近似模板去重。
2. 将剩余邮件聚成 100 个簇。
3. 每个簇检查 10 封代表样本，共检查约 1,000 封。
4. 对明显高纯度的簇进行候选标签传播。
5. 从混合簇中再标注约 1,000 封。
6. 使用约 2,000 封人工标签训练第一版逻辑回归。
7. 选择 500～1,000 封最不确定的邮件继续标注。
8. 独立保留数百至数千封人工确认邮件作为最终测试集。

实际数量需要根据聚类纯度和邮件多样性进行调整。

## 六、需要避免的风险

### 1. 直接给整个簇统一标注

少量正常邮件可能混入垃圾簇，形成错误训练标签。因为正常邮件误拦截的代价很高，这种错误尤其危险。

### 2. 使用同一批伪标签进行训练和测试

这只能证明模型学会模仿聚类结果，不能证明模型真的能识别垃圾邮件。

测试集必须由人工确认，而且不应进行标签传播。

### 3. 将近似重复模板分到训练集和测试集

这会使测试指标虚高。相同或近似相同的模板必须放在同一个数据分区。

### 4. 只标注明显垃圾邮件

训练集还必须包含大量“看起来像垃圾但实际正常”的困难样本，例如：

- 合法营销订阅。
- 密码重置邮件。
- 银行安全通知。
- 公司群发通知。
- 发票和付款提醒。

这些样本最能帮助模型降低正常邮件误判率。

## 七、最终建议

可将最初的想法调整为：

```text
使用 K-Means 寻找相似邮件
→ 人工抽查每个簇
→ 只对高纯度簇传播候选标签
→ 对混合簇和边界样本继续人工标注
→ 使用监督模型训练最终分类器
```

K-Means 可以显著减少重复模板的标注工作，但不能替代人工标注。真正节省标注时间的关键通常是：

```text
去重 + 聚类抽样 + 主动学习
```
