# 机器学习数据集获取与挑选指南

## 问题

我现在已经大概知道机器学习的原理了，但是对获取训练数据集仍然知之甚少。不知道有哪些平台可以获取高质量的数据集，也不知道应该如何挑选数据集，是否可以提供一些指导？

## 回答

获取数据集并不是“找一个下载量最高的文件”，而是要判断它是否真正代表自己的业务问题。

一个很重要的观念是：

> 高质量数据集不一定规模最大、最干净，而是与模型未来面对的真实数据足够相似，并且标签可信。

## 一、常用的数据集平台

不同平台适合不同目的。

| 平台 | 适合的数据 | 特点 |
| --- | --- | --- |
| [Kaggle Datasets](https://www.kaggle.com/datasets) | 表格、文本、图像、竞赛数据 | 数量多、容易下载，适合练习和原型验证 |
| [UCI Machine Learning Repository](https://archive.ics.uci.edu/) | 传统机器学习表格数据 | 数据规模通常不大，说明较完整，适合学习算法 |
| [OpenML](https://www.openml.org/) | 表格数据、标准机器学习任务 | 数据集、任务和模型结果可以关联，便于比较算法 |
| [Hugging Face Datasets](https://huggingface.co/datasets) | NLP、文本、语音、图像、多模态 | 文本数据尤其丰富，很多数据可以直接用 Python 加载 |
| [Google Dataset Search](https://datasetsearch.research.google.com/) | 跨平台搜索 | 它是数据集搜索引擎，可以搜索大学、政府和研究机构的数据 |
| [阿里云天池](https://tianchi.aliyun.com/dataset) | 中文、商业、电商、工业数据 | 国内访问方便，包含竞赛和行业数据 |
| [DataFountain](https://www.datafountain.cn/datasets) | 中文、政务、工业和竞赛数据 | 国内真实业务题目相对较多 |
| 论文和项目官方网站 | 某个细分领域的权威数据 | 通常数据来源最明确，但下载和处理可能更复杂 |
| 政府开放数据平台 | 人口、交通、气象、经济、医疗统计 | 来源可靠，但不一定已经整理成机器学习格式 |

可以按照下面的方式选择平台：

- 学习传统机器学习：优先 UCI、OpenML；
- 寻找通用项目数据：优先 Kaggle；
- 寻找文本、图像、语音数据：优先 Hugging Face；
- 寻找中文和国内业务数据：优先天池、DataFountain；
- 不知道数据在哪里：使用 Google Dataset Search。

Hugging Face 的优势是很多数据集附带 Dataset Card，可以查看来源、用途、字段、许可证和已知限制，而不只是下载一个来历不明的文件。参见 [Hugging Face 数据集说明](https://huggingface.co/docs/hub/main/datasets)。

## 二、先定义问题，再搜索数据

不要一开始就搜索“机器学习数据集”。先把业务问题整理清楚。

| 项目 | 垃圾邮件项目示例 |
| --- | --- |
| 模型任务 | 二分类 |
| 输入是什么 | 原始 EML 邮件 |
| 输出是什么 | 正常邮件或垃圾邮件 |
| 预测发生在什么时候 | 邮件到达业务系统时 |
| 可用特征 | 主题、正文、发件人、邮件头、链接、附件信息 |
| 目标语言 | 中文为主，可能包含英文 |
| 真实数据分布 | 正常邮件较多，垃圾邮件较少 |
| 错误代价 | 把正常邮件误判为垃圾邮件的代价较高 |
| 数据时间范围 | 越接近当前业务越好 |

然后再组合关键词搜索，例如：

```text
email spam classification dataset
raw email spam corpus RFC822
spam ham eml dataset
phishing email dataset
Chinese spam email dataset
垃圾邮件 分类 数据集
钓鱼邮件 原始邮件 数据集
```

搜索时可以加入格式和语言要求：

```text
raw email
RFC822
EML
Chinese
labeled
license
```

这比只搜索 `spam dataset` 更容易找到适合的数据。

## 三、如何判断数据集质量

### 1. 数据是否与业务输入一致

如果业务系统收到的是完整 EML，而数据集只有：

```csv
text,label
"Congratulations, you won...",spam
```

它虽然可以训练正文分类模型，却无法训练和验证以下特征：

- 发件人地址；
- 邮件主题；
- HTML 结构；
- 链接数量；
- `Reply-To` 与 `From` 是否一致；
- 附件名称和类型；
- 邮件头异常。

因此，对垃圾邮件项目来说，原始 EML/RFC822 语料通常比只有正文的 CSV 更有价值。

### 2. 标签是否可信

需要确认：

- 谁标注的？
- 标签是人工确认，还是规则自动生成？
- 有没有多人交叉标注？
- 是否说明过容易混淆的情况？
- 是否包含无法确定的样本？
- 标签含义是否与自己的业务一致？

例如，有些数据集把营销邮件算作正常邮件，有些将其算作垃圾邮件。如果业务定义不同，直接训练会产生系统性错误。

建议随机抽查每个类别至少几十封。发现明显错标时，不要因为它被称为“知名数据集”就忽略问题。

### 3. 数据来源是否明确

可以参考以下优先级：

```text
政府、大学、研究机构、竞赛官方
                 >
有完整说明和许可证的个人数据集
                 >
只有文件、没有来源说明的数据集
```

在 Kaggle 等社区平台上，一个数据集下载量很高，并不代表其原始来源、标签或许可证一定可靠。最好沿着数据集描述找到最初发布者。

### 4. 数据是否有代表性

检查数据是否覆盖真实业务中会出现的情况：

- 中文、英文和中英混合；
- 纯文本和 HTML 邮件；
- 短邮件和长邮件；
- 营销、诈骗、钓鱼和群发广告；
- 正常通知、验证码、账单和订阅邮件；
- 带附件和不带附件；
- 不同发件人和不同邮件系统；
- 最新的垃圾邮件表达方式。

公开垃圾邮件语料往往较老，模型可能学到旧时代的词汇，却识别不了近期中文钓鱼邮件。

### 5. 数据是否重复或泄漏

这是非常常见的问题。

同一个邮件模板可能只替换了收件人姓名，然后同时进入训练集和测试集。模型相当于“见过答案”，测试准确率就会虚高。

邮件数据不建议只用普通随机划分，最好考虑：

- 按邮件模板分组；
- 按发件人或域名分组；
- 按时间划分；
- 将重复邮件和近似重复邮件放在同一集合。

更接近生产环境的划分方式是：

```text
较早邮件 → 训练集
较新邮件 → 验证集和测试集
```

这可以检验模型是否能识别未来出现的新邮件。

### 6. 类别分布是否合理

假设真实业务中只有 5% 是垃圾邮件，而训练数据中垃圾和正常邮件各占 50%，模型训练虽然方便，但评估结果可能无法反映线上表现。

需要分别记录：

```text
训练集类别比例
验证集类别比例
真实业务类别比例
```

训练时可以调整类别权重，但测试集最好尽量接近真实业务分布。

### 7. 时间是否足够新

垃圾邮件、欺诈、风控、推荐和网络安全领域变化特别快。

一个十年前的数据集可以用来：

- 学习；
- 调试代码；
- 验证训练流程；
- 提供一部分基础样本。

但不应该单独承担生产模型训练。对于这些领域，近期的小数据有时比古老的大数据更有价值。

### 8. 许可证是否允许使用

下载前检查：

- 能否用于商业用途；
- 能否修改和重新分发；
- 是否需要署名；
- 是否仅限学术研究；
- 是否包含个人信息；
- 是否允许将训练出的模型用于业务。

如果没有明确许可证，不要默认它可以用于商业系统。

## 四、下载后先做数据验收

不要拿到数据就立即训练。建议先生成一份数据质量报告，至少检查：

```text
总样本数
每个类别的数量和比例
空主题、空正文的数量
无法解析的邮件数量
语言分布
正文长度分布
HTML与纯文本比例
附件比例
完全重复邮件数量
近似重复邮件数量
时间范围
发件人和域名数量
随机抽样检查结果
```

然后人工打开一些样本：

- 每个类别随机抽取 50 封；
- 抽取模型最容易混淆的邮件；
- 抽取特别短和特别长的邮件；
- 检查是否有乱码、错标、解析失败；
- 检查正文是否被错误截断；
- 检查标签是否符合自己的业务定义。

数据集能成功被 `pandas` 读取，只代表格式有效，不代表它适合训练。

## 五、学习数据和生产数据要分开看待

可以把数据集分成三个层次。

### 第一层：教学数据

例如 Iris、Titanic、Wine Quality。

用途是理解：

- 特征和标签；
- 训练集与测试集；
- 分类和回归；
- 模型评价；
- 数据预处理。

这类数据通常很规整，但与真实业务差距较大。

### 第二层：公开领域数据

例如 SpamAssassin、TREC、Enron。

用途是：

- 跑通完整项目；
- 建立第一个可用模型；
- 比较不同算法；
- 补充自己的样本。

它比教学数据真实，但可能存在年代、语言、来源和业务定义差异。

### 第三层：自己的业务数据

这是生产模型最重要的数据，包括：

- 线上真实输入；
- 用户反馈；
- 人工确认结果；
- 模型误判样本；
- 新出现的业务场景。

最终模型的数据结构应该逐渐从：

```text
大量公开数据 + 少量业务数据
```

转变为：

```text
适量公开数据 + 大量高质量业务数据
```

## 六、适合垃圾邮件项目的数据策略

### 冷启动阶段

可以使用：

- SpamAssassin 的 `spam`、`spam_2`；
- SpamAssassin 的 `easy_ham`、`hard_ham`；
- TREC 垃圾邮件语料；
- 少量人工确认的自有 EML 邮件。

目标是先得到第一个基线模型。

### 业务适配阶段

从自己的未标注邮件中分层抽样：

- 模型认为非常像垃圾邮件的；
- 模型认为非常像正常邮件的；
- 模型置信度接近 50% 的；
- 规则检测和模型判断不一致的；
- 新发件人、新域名和新模板邮件。

其中最值得人工标注的是“不确定样本”和“规则与模型冲突样本”，因为它们通常能够给模型带来最大提升。这种方式属于主动学习，比从大量邮件中完全随机标注更节省时间。

### 上线评估阶段

单独保留一批近期业务邮件：

```text
训练集：公开数据 + 较早的业务标注数据
验证集：较新的业务标注数据
测试集：最近且从未参与调参的业务标注数据
```

测试时不要只看准确率，重点关注：

- 垃圾邮件召回率；
- 正常邮件误杀率；
- Precision；
- Recall；
- F1；
- 混淆矩阵。

对于邮件系统，正常邮件误杀通常比漏掉少量垃圾邮件更严重。因此，分类阈值不一定固定为 `0.5`，应该根据业务容忍度调整。

## 七、数据集选择清单

准备下载某个数据集时，依次回答：

```text
[ ] 任务类型与我的问题一致吗？
[ ] 输入格式与线上数据一致吗？
[ ] 标签定义与我的业务一致吗？
[ ] 数据来源和标注方法明确吗？
[ ] 数据语言、时间和场景接近业务吗？
[ ] 样本数量和类别比例合理吗？
[ ] 是否检查过重复与数据泄漏？
[ ] 是否有明确许可证？
[ ] 是否随机人工检查过样本？
[ ] 是否保留了独立的真实业务测试集？
```

如果前四项中有任何一项无法确认，这个数据集最好只用于学习或实验，不要直接用于生产模型。

最后可以将挑选原则概括为：

> 平台负责帮你发现数据，数据说明帮助你理解数据，人工抽查帮助你相信数据，而真实业务测试才决定这个数据是否真正有用。
