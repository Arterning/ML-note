# 基于机器学习的垃圾邮件识别方案

## 一、推荐方案概览

建议第一版采用：

```text
词级与字符级 TF-IDF
        +
邮件结构化特征
        +
逻辑回归
        +
可调分类阈值
```

完整处理流程：

```text
邮件原文
  ↓
文本与邮件头清洗
  ↓
TF-IDF 提取文本特征
  ├── 词级 n-gram
  └── 字符级 n-gram
  ↓
拼接邮件元数据特征
  ↓
逻辑回归二分类
  ↓
垃圾邮件概率
  ↓
根据阈值决定：正常 / 可疑 / 垃圾
```

这种方案训练速度快、容易解释、支持概率输出，对中小规模数据也比较友好，不必一开始就使用深度学习。

## 二、模型选择

首选模型：

```python
TF-IDF + LogisticRegression
```

选择逻辑回归的原因：

- 适合高维、稀疏的文本特征。
- 训练和预测速度快。
- 数据量不大时也能取得不错效果。
- `predict_proba()` 可以输出垃圾邮件概率。
- 可以分析哪些词语对分类结果贡献较大。
- 方便根据业务风险调整分类阈值。

建议同时建立两个对照模型：

- `MultinomialNB`：训练极快，适合作为最简单的基线。
- `LinearSVC`：文本分类效果通常很好，但原生不输出概率。

第一版可以使用逻辑回归作为主模型，朴素贝叶斯作为基线模型。

## 三、输入特征

### 1. 邮件主题和正文

可以把邮件主题和正文拼接起来：

```text
邮件主题 + 正文
```

建议同时提取词级和字符级 TF-IDF 特征。

词级特征可以识别：

- 免费领取
- 限时优惠
- 点击链接
- 账户异常
- 立即验证

一个可行的词级配置：

```python
TfidfVectorizer(
    analyzer="word",
    ngram_range=(1, 2),
    min_df=2,
    max_df=0.98,
    sublinear_tf=True,
)
```

字符级特征可以识别错别字、变形词、网址、乱码，以及故意插入符号的内容。

一个可行的字符级配置：

```python
TfidfVectorizer(
    analyzer="char",
    ngram_range=(2, 5),
    min_df=2,
    sublinear_tf=True,
)
```

对于中文垃圾邮件，字符级 n-gram 往往很有用，因为它不完全依赖中文分词。

### 2. 邮件元数据

除了文本，还可以加入以下结构化特征：

- 发件人是否在联系人列表中。
- 发件人域名是否异常。
- 发件人与回复地址是否一致。
- 邮件中 URL 的数量。
- URL 域名数量。
- 是否包含短链接或 IP 地址链接。
- 附件数量和附件类型。
- 大写字母、感叹号和货币符号的数量。
- HTML 内容占比。
- 邮件正文长度。
- 收件人数量。
- 是否缺少常见邮件头。
- SPF、DKIM 和 DMARC 验证结果。

TF-IDF 负责分析邮件内容，元数据则帮助识别伪造、群发和钓鱼行为。

## 四、标签设计

第一版建议采用二分类：

```text
0 = 正常邮件
1 = 垃圾邮件
```

如果以后数据充足，可以扩展为：

```text
正常邮件
营销邮件
普通垃圾邮件
钓鱼邮件
恶意附件邮件
```

第一版不建议划分过细。类别过多而每类样本不足时，模型更难获得稳定效果。

## 五、数据集划分

不要直接随机拆分全部邮件，否则可能产生数据泄漏。

例如，同一个群发模板可能同时出现在训练集和测试集。模型只需记住模板就能获得很高的测试分数，但遇到新模板时可能表现很差。

推荐做法：

- 按时间划分，使用较早的邮件训练，较新的邮件测试。
- 相同模板或近似重复邮件放入同一个集合。
- 同一发件人或同一批群发邮件尽量不要跨训练集和测试集。
- 单独保留一份最新邮件作为最终测试集。

一种参考比例：

```text
训练集：70%
验证集：15%
测试集：15%
```

## 六、类别不平衡

真实数据中，正常邮件和垃圾邮件的数量可能差距很大。

逻辑回归可以尝试设置：

```python
LogisticRegression(
    class_weight="balanced",
    max_iter=2000,
)
```

是否使用 `class_weight="balanced"` 应根据验证结果决定。它可能提高垃圾邮件召回率，同时也可能增加正常邮件被误判的数量。

## 七、评估指标

不能只看 Accuracy。

假设 95% 的邮件都是正常邮件，即使模型把所有邮件都预测为正常，也能得到 95% 的准确率，但它没有识别出任何垃圾邮件。

应该重点评估：

- Precision：判定为垃圾邮件的样本中，有多少确实是垃圾邮件。
- Recall：所有垃圾邮件中，有多少被模型成功识别。
- F1：Precision 和 Recall 的综合指标。
- PR-AUC：类别不平衡时很有参考价值。
- 混淆矩阵。
- 正常邮件误判率。

垃圾邮件系统尤其需要关注：

```text
正常邮件 → 被错误放入垃圾邮件箱
```

这种错误通常比少量垃圾邮件进入收件箱更加严重。

## 八、分类阈值

不建议不经验证就直接使用固定的 `0.5` 阈值。

逻辑回归可以输出垃圾邮件概率，因此可以设计三级处理：

```text
概率 < 0.30         → 正常收件箱
0.30 ≤ 概率 < 0.85  → 可疑邮件，保留但进行标记
概率 ≥ 0.85         → 垃圾邮件箱
```

这些数字只是示例，具体阈值应根据验证集和业务成本确定。

- 如果正常邮件误判的代价很高，应提高垃圾邮件阈值。
- 如果更加重视垃圾邮件拦截率，可以适当降低阈值。

## 九、第一版技术组合

```text
数据处理：
    pandas + Python email 标准库

文本特征：
    scikit-learn TfidfVectorizer
    - word n-gram: (1, 2)
    - char n-gram: (2, 5)

结构化特征：
    URL 数量、附件数量、正文长度、发件人域名等

模型：
    LogisticRegression

训练流程：
    Pipeline + FeatureUnion / ColumnTransformer

评估：
    Precision、Recall、F1、PR-AUC、混淆矩阵

模型保存：
    joblib
```

## 十、什么时候考虑深度学习

出现以下情况时，可以考虑中文 BERT、RoBERTa 或其他 Transformer：

- 已经积累了较多且标签可靠的邮件。
- 垃圾内容依赖复杂语义，TF-IDF 难以识别。
- 攻击者频繁使用同义改写规避关键词。
- 对效果上限的要求较高。
- 可以接受更高的训练和部署成本。

即使采用深度学习，邮件头、URL、附件和域名等结构化特征仍然有用。实际系统通常由文本模型、结构化安全特征和规则系统共同组成。

## 十一、推荐开发顺序

1. 收集并清洗带标签的邮件。
2. 对敏感信息进行脱敏，限制原始邮件的访问权限。
3. 去除完全重复和近似重复的邮件。
4. 按时间、模板或邮件来源划分数据集。
5. 建立朴素贝叶斯基线。
6. 训练词级与字符级 TF-IDF + 逻辑回归。
7. 加入邮件头、URL、附件和域名等结构化特征。
8. 使用 Precision、Recall、F1、PR-AUC 和混淆矩阵评估。
9. 根据正常邮件误判成本调整分类阈值。
10. 持续分析错误样本并补充训练数据。
11. 当传统模型效果遇到瓶颈后，再评估 Transformer。

## 十二、最终建议

第一版优先实现：

```text
字符/词语 TF-IDF
        +
邮件结构化特征
        +
逻辑回归
        +
可调分类阈值
```

这是模型效果、训练成本、推理速度、可解释性和部署难度之间比较均衡的方案。
